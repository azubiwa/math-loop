# Level 1：10回分一括生成プロンプト

```text
あなたは、数学の問題作成・校正・解説執筆を担当する専門家です。
学習アプリ「MathLoop」向けに、Level 1の独立したコンテスト10回分を一括作成してください。

## 作成数

- 「Level 1 #001」から「Level 1 #010」までの10回分
- 各回A、B、C、D、Eを1問ずつ
- 合計50問。欠番、重複、追加問題は禁止
- 配列内の順序は #001-A, #001-B, ... #001-E, #002-A, ... #010-E とする

## 想定レベル

高校数学の発展内容から大学1〜2年程度までを対象にする。
単なる計算速度ではなく、定義の理解、標準的な論証、複数の知識を結び付ける力を段階的に問う。

- A: 定義・公式を直接使うウォームアップ。目安5分、100点
- B: 標準的な計算または短い説明。目安10分、200点
- C: 2〜3段階の推論を要する標準問題。目安20分、300点
- D: 複数の概念を組み合わせる発展問題。目安30分、400点
- E: 方針の発見や丁寧な証明を要する回の主問題。目安45分、500点

同じ回ではAからEへ明確に難しくなるようにする。ただしAを単純すぎる暗記問題、Eを未習事項頼みの問題にしない。

## 分野構成

10回全体で次の分野を偏りなく扱う。1回の中でも可能な範囲で題材を散らす。

- 微積分：極限、微分、積分、級数、関数列の初歩
- 線形代数：行列、連立一次方程式、線形写像、固有値、対角化
- 集合・論理・証明：量化、写像、同値関係、帰納法、背理法
- 代数学の初歩：群、環、合同式、多項式
- 位相・解析の初歩：開集合、閉集合、コンパクト性、連続性
- 確率・統計の初歩：期待値、分散、条件付き確率、基本的な分布
- 常微分方程式の初歩

50問の題意や解法が実質的に重複しないようにする。同じ定理を使う場合も、問う観点を変える。

## JSON出力

出力は有効なJSON配列だけにする。Markdown、コードフェンス、前置き、後書き、コメント、省略記号は一切出力しない。
JSON文字列内のバックスラッシュは正しくエスケープする。すべてのキーと文字列をダブルクォートで囲む。

各問題を必ず次のスキーマで作る。

{
  "id": "L1-001-A",
  "contest": "Level 1 #001",
  "difficulty": "A",
  "score": 100,
  "title": "簡潔で内容が分かるタイトル",
  "field": "主分野を1つ",
  "tags": ["具体的な知識タグ", "具体的な知識タグ"],
  "minutes": 5,
  "answerType": "short または proof",
  "prompt": ["自己完結した問題文", "必要な条件や数式"],
  "note": "必要な場合だけ記載する注記",
  "explanation": {
    "summary": "最終的な答えと解法の要点",
    "steps": [
      "途中を飛ばさない解法の第1段階",
      "根拠を明示した解法の第2段階",
      "結論"
    ],
    "knowledge": [
      {
        "title": "この問題に必要な定義",
        "body": "定義を簡潔かつ正確に説明し、この問題との関係も述べる。"
      },
      {
        "title": "使用する定理または公式",
        "body": "仮定と結論を簡潔に示し、この問題で仮定が満たされる理由も述べる。"
      }
    ]
  },
  "grade": {
    "type": "exact または keywords",
    "accepted": ["完全一致で認める正答表記"],
    "hint": "答え方についての短いヒント"
  }
}

noteが不要ならnoteキーを省略する。
grade.typeが"exact"ならacceptedを使い、groupsは出力しない。
grade.typeが"keywords"ならacceptedは出力せず、代わりに次の形のgroupsを使う。

{
  "type": "keywords",
  "groups": [
    ["必須論点1の表現", "同じ論点の別表記"],
    ["必須論点2の表現", "同じ論点の別表記"],
    ["最終結論の表現", "最終結論の別表記"]
  ],
  "hint": "証明に含めるべき内容を答えそのものにならない範囲で示す。"
}

## 問題文の品質基準

- 問題文だけで対象、仮定、記号、答える内容が一意に分かるようにする。
- 外部資料、図、未提示の前問を参照しない。
- 使用する数値や関数は、意図した解法で破綻しないことを実際に検算する。
- 定理の仮定を満たさない問題を作らない。
- 「証明せよ」としながら偽の命題を出さない。反例問題なら反例を求めることを明記する。
- shortは答えが短い文字列で一意に判定できる問題だけにする。
- proofは結論だけでなく根拠を採点したい問題に使う。
- 数式はUnicodeまたは簡潔なTeX風表記にし、同じ問題内で記法を統一する。

## 解説と周辺知識

- explanation.summaryには最終答案を明記する。
- explanation.stepsは、学習者が途中式や論理を再現できる具体性を持たせる。
- 各stepで、変形や主張の根拠となる定義・公式・定理を明示する。
- knowledgeは原則2〜4項目にする。
- knowledgeには、必要な定義、中心となる定理、その適用条件、混同しやすい類似概念を簡潔にまとめる。
- 問題に直接不要な百科事典的説明は避ける。
- 「明らか」「同様に」だけで重要な推論を省略しない。
- E問題でも学部前半の知識から理解できる解説にする。

## 採点条件

exact採点は回答全体の完全一致である。acceptedには正しい別表記を十分に列挙するが、誤答や近似値を混ぜない。
数値の許容誤差判定はできないため、丸め誤差が生じる問題は避ける。

keywords採点では、groupsの各配列を独立した必須論点1つに対応させる。
同じgroup内には同義表現だけを置く。一般語1語だけの条件は誤検出しやすいので避ける。
模範解答の主要論点がすべてgroupsに対応し、groupsの語句が実際にstepsの内容と整合するようにする。

## IDとメタデータ

- idはL1-001-AからL1-010-Eまでとする。
- contestはidの回号と一致させる。
- difficulty、score、minutesは上記の難易度表に合わせる。
- tagsは2〜5個とし、検索に役立つ具体語を使う。

## 出力前の内部検査

出力前に全50問を内部で検査する。検査結果は出力しない。

1. 各問題を実際に解き、問題・答え・解説に矛盾がないか。
2. 10回 × 5問が揃い、ID、contest、difficultyに欠番や重複がないか。
3. AからEの難易度差が適切か。
4. explanationの最終結論とgradeの正答条件が一致しているか。
5. knowledgeの定義・定理が正確で、適用条件が説明されているか。
6. exactのacceptedで代表的な正答表記を採点できるか。
7. keywordsのgroupsが必須論点を過不足なく表すか。
8. JSONとして構文が完全に正しく、余計な文章がないか。

一度に50問すべてを省略せず出力してください。
```
