# Level 2：10回分一括生成プロンプト

```text
あなたは、数学の問題作成・校正・解説執筆を担当する専門家です。
学習アプリ「MathLoop」向けに、Level 2の独立したコンテスト10回分を一括作成してください。

## 作成数

- 「Level 2 #001」から「Level 2 #010」までの10回分
- 各回A、B、C、D、Eを1問ずつ
- 合計50問。欠番、重複、追加問題は禁止
- 配列内の順序は #001-A, #001-B, ... #001-E, #002-A, ... #010-E とする

## 想定レベル

Level 2は大学3〜4年程度の基礎を対象にする系列である。
学部後半で学ぶ主要分野の定義・標準定理を確実に使い、仮定の精査、標準的な証明、反例構成、複数命題の組合せを問う。現行Level 3の基本問題に相当する難易度を基準にする。

- A: 学部後半の基本定義・標準定理を正しく使う問題。目安15分、200点
- B: 仮定の確認を含む標準的な証明・計算。目安25分、300点
- C: 複数の命題を組み合わせる問題、または反例構成。目安40分、400点
- D: 非自明な補題や着眼を要する発展問題。目安60分、500点
- E: 1分野内で深い方針立てを要する主問題。目安90分、700点

同じ回ではAからEへ明確に難しくする。難しさを煩雑な計算量だけで作らない。50問の題意、結論、中心的な解法が実質的に重複しないようにする。

## 分野構成

10回全体で次を偏りなく扱う。

- 実解析：距離空間、完備性、関数列、一様収束、測度、Lebesgue積分の基礎
- 複素解析：正則関数、Cauchyの積分定理、留数の基礎
- 線形代数・関数解析の初歩：双対、内積空間、スペクトル、ノルム空間
- 抽象代数：群作用、Sylowの定理、環・イデアル、体拡大の初歩
- 位相空間論：コンパクト性、連結性、商空間、積位相、分離公理
- 微分幾何・多様体の初歩：接空間、正則値
- 確率論、常微分方程式：確率変数の収束、条件付き期待値、存在一意性、線形系

## JSON出力

出力は有効なJSON配列だけにする。Markdown、コードフェンス、前置き、後書き、コメント、省略記号は一切出力しない。
JSON文字列内のバックスラッシュは正しくエスケープし、すべてのキーと文字列をダブルクォートで囲む。

各問題を必ず次のスキーマで作る。

{
  "id": "L2-001-A",
  "contest": "Level 2 #001",
  "difficulty": "A",
  "score": 200,
  "title": "簡潔で内容が分かるタイトル",
  "field": "主分野を1つ",
  "tags": ["具体的な知識タグ", "具体的な知識タグ"],
  "minutes": 15,
  "answerType": "short または proof",
  "prompt": ["自己完結した問題文", "必要な条件や数式"],
  "note": "必要な場合だけ記載する注記",
  "explanation": {
    "summary": "最終的な結論と解法・証明の要点",
    "steps": [
      "使う定義・定理と適用条件の確認",
      "根拠を明示した主要な推論",
      "結論"
    ],
    "knowledge": [
      {
        "title": "必要な定義",
        "body": "定義を正確に説明し、この問題との関係を述べる。"
      },
      {
        "title": "中心となる定理",
        "body": "定理の仮定と結論、この問題で仮定を満たす理由を示す。"
      },
      {
        "title": "関連概念・注意点",
        "body": "類似概念との差、典型的な誤り、または関連する反例を簡潔にまとめる。"
      }
    ]
  },
  "grade": {
    "type": "keywords",
    "groups": [
      ["必須論点1の表現", "同じ論点の別表記"],
      ["必須論点2の表現", "同じ論点の別表記"],
      ["最終結論の表現", "最終結論の別表記"]
    ],
    "hint": "答えを直接明かさずに、方針を示す短いヒント"
  }
}

noteが不要ならnoteキーを省略する。
proofには原則keywordsを使う。groupsの各配列は、模範解答における独立した必須論点1つだけを表す。同じgroupに別の論点を混ぜない。
shortは、答えが短い文字列で一意に判定できる問題だけに使う。shortではgroupsを出力せず、次のexact形式にする。

{
  "type": "exact",
  "accepted": ["正答", "数学的に同値な別表記"],
  "hint": "回答形式についての短いヒント"
}

## 問題文の品質基準

- 問題文だけで対象、仮定、記号、答える内容が一意に分かるようにする。
- 外部資料、図、未提示の前問を参照しない。
- 使用する数値や関数を実際に検算し、定理の仮定を満たさない問題を作らない。
- 反例を問う場合は、どの条件を外したときの反例かを明記する。
- 数式はUnicodeまたは簡潔なTeX風表記にし、同じ問題内で記法を統一する。

## 解説と周辺知識

- summaryには最終結論だけでなく、中心となる着眼を明記する。
- stepsでは重要な計算、論理、定理の適用理由を「明らか」だけで飛ばさない。
- knowledgeは原則3〜5項目にする。
- knowledgeには、必要な定義、使用定理の仮定と結論、その適用理由に加え、類似概念との差、典型的な反例、または関連定理を含める。
- 問題と無関係な百科事典的説明で水増ししない。

## 採点条件

exactは回答全体の完全一致である。acceptedには代表的な正答表記を列挙するが、誤答や近似値を混ぜない。許容誤差が必要な問題は作らない。

keywordsでは、groupsの各配列を独立した必須論点に対応させる。一般語1語だけの条件は誤検出しやすいため避ける。模範解答の主要論点がすべてgroupsで確認でき、結論だけの答案が正解にならないようにする。

## IDと最終確認

- idはL2-001-AからL2-010-Eまで一意にする。
- contestはidの回号と一致させる。
- difficulty、score、minutesは上記の難易度表に合わせる。
- tagsは2〜5個とし、検索に役立つ具体語を使う。

出力前に全50問を内部で検査する。問題・答え・解説・周辺知識・採点条件の数学的整合性、定理の適用条件、JSON構文、IDの重複と欠番を確認する。検査結果は出力しない。一度に50問すべてを省略せず出力する。
```
