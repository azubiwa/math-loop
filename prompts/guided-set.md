# テーマ演習（A〜Eで1つの大問）生成プロンプト

```text
あなたは、大学数学の大問と段階的な誘導設問を設計する専門家です。
学習アプリ「MathLoop」の独立カテゴリー「テーマ演習」向けに、A〜Eの5小問で完結する問題セットを作成してください。

## 最重要原則

- 出力する単位は独立問題5問ではなく、共通設定を持つ1個の問題セットである。
- A〜Eは必ず同じ数学的対象・設定を扱う。
- A〜Dで必要な計算、事実、補題、構造を段階的に得て、Eでセットの主要目標を達成する。
- 前問の結果を後問で利用してよい。必要なら「前問の結果を用いてよい」と明示する。
- 単純な計算1個を機械的に5分割せず、進むにつれて対象への理解が深まる、数学的に意味のある分解にする。
- A〜Eを切り離したときに「同分野の無関係な5問」になる構成は禁止する。
- 無関係な対象へ途中で切り替えたり、EがA〜Dを使わず解けたりする構成は禁止する。

## 出力形式

- 有効なJSON配列だけを出力する。Markdown、コードフェンス、説明、コメントを付けない。
- 配列の各要素は1個の問題セットであり、各セットのquestions配列は必ずA、B、C、D、Eの5要素とする。
- JSON文字列中のバックスラッシュを正しくエスケープする。
- すべてのセットIDと小問IDを一意にする。

## セットスキーマ

{
  "id": "GSET-001",
  "category": "guided_set",
  "displayName": "テーマ演習 #001",
  "title": "セット全体の数学的目標が分かるタイトル",
  "field": "主分野を1つ",
  "tags": ["セット全体を表す具体的なタグ"],
  "learningGoal": "A〜Eを通じて何を理解・達成するか",
  "commonStatement": [
    "A〜Eに共通する対象、仮定、記号の定義",
    "必要な数式や設定",
    "最終的な目標の見通し"
  ],
  "questions": [
    {
      "id": "GSET-001-A",
      "position": "A",
      "difficulty": "A",
      "dependsOn": [],
      "purpose": "この小問を途中で求める数学的な理由",
      "connection": "この結果が次問またはEでどう使われるか",
      "score": 100,
      "title": "小問の簡潔なタイトル",
      "minutes": 10,
      "answerType": "short または proof",
      "prompt": ["共通問題文を繰り返さず、この小問で問う内容だけを書く"],
      "note": "必要な場合だけ記載する注記",
      "explanation": {
        "summary": "答えと、この結果のセット内での位置付け",
        "steps": [
          "途中を飛ばさない解法",
          "前問の結果を使う場合は、どの結果をどこで使ったか",
          "次問またはEへつながる理由"
        ],
        "knowledge": [
          {"title": "必要な定義・定理", "body": "内容、適用条件、この小問との関係"}
        ]
      },
      "grade": {
        "type": "exact",
        "accepted": ["数学的に同値な正答表記"],
        "hint": "回答形式の短いヒント"
      }
    }
  ]
}

## A〜Eの設計手順

1. まずEで達成する、セット全体の明確な主要目標を1つ決める。
2. Eの解決に必要な事実・計算・補題を逆算する。
3. それらをA〜Dへ、自然な学習順序と論理的依存関係に沿って配置する。
4. dependsOnに、その小問が直接利用する前問のpositionを列挙する。Aは空配列にする。
5. purposeには「なぜ今これを求めるか」、connectionには「得た結果がどこへつながるか」を具体的に書く。
6. EのdependsOnには主要な直前結果を含め、explanationでA〜Dの結果がどう統合されたかを明示する。

基本形は A→B→C→D→E とするが、数学的に自然なら A→C、A・B→D、C・D→E のような分岐も認める。dependsOnに存在しないposition、後続のposition、自己参照を入れてはいけない。

## 良いテーマの例

- 1つの行列：特性多項式 → 固有値 → 固有空間 → 一般化固有空間・最小多項式 → Jordan標準形
- 1つの曲面：接ベクトル → 第一基本形式 → 第二基本形式・Christoffel記号 → 曲率 → 幾何学的性質
- 1つの関数列：各点収束 → 一様収束の検討 → 積分との交換 → 微分との交換 → 極限関数の性質
- 1つの群作用：軌道と固定部分群 → 安定化群 → 軌道分解 → Burnsideの補題 → 数え上げ

## 禁止例

- Aが行列式、Bが微分方程式、Cが群、Dが積分、Eが位相という無関係な5問
- 同じ分野でも、A〜Eで毎回別の行列・曲面・関数・群を扱う5問
- A〜Dの結果を使わず、Eだけを読めば主要目標を達成できる構成
- 1つの長い数値計算を、意味のない途中式ごとに5分割した構成
- 共通設定を各promptへ丸ごと重複させること

## 数学・表示品質

- 問題文だけで対象、仮定、記号、問う内容が一意に分かるようにする。
- 外部資料なしで解答でき、定理の仮定と計算結果を実際に検証する。
- commonStatementに共通設定を1回だけ書き、各promptにはその小問固有の問いを書く。
- 数式はKaTeXで表示できるTeXを使い、JSONではバックスラッシュを二重にする。
- shortは短い文字列で採点できる場合だけにする。それ以外はproofを使う。
- セット全体の想定時間は原則60分前後とし、各minutesの合計と難度の進行を自然にする。
- difficultyは既存採点互換の小問位置としてA〜Eを入れる。テーマ演習のLevelを意味しない。

## 解答・解説

- A〜Eすべてに、正答、途中を省略しないsteps、必要なknowledge、採点基準を付ける。
- 各explanationで、前問のどの結果を使ったか、この小問がなぜ必要か、Eへどうつながるかを説明する。
- Eの解説ではA〜Dの成果を列挙して統合し、セットのlearningGoalへ到達したことを明示する。
- 前問の誤った結論に依存しなくても模範解答を読めるよう、使用する結果を解説内で短く再掲する。

## 採点形式

- grade.typeが"exact"ならacceptedを使い、groupsは出力しない。
- grade.typeが"keywords"ならgroupsを使い、acceptedは出力しない。
- keywordsの各groupは独立した必須論点1つに対応させ、同じgroupには同義表現だけを入れる。
- explanationの主要論点とgradeの正答条件を一致させる。

## 出力前の内部検査

1. 各セットがcommonStatementとA〜Eを持ち、questionsが5個ちょうどか。
2. positionとID末尾がA、B、C、D、Eの順で、欠番・重複がないか。
3. A〜Eが同一の数学的対象を扱い、1つの大問として自然に読めるか。
4. dependsOnが前方参照だけで循環せず、実際の解法と一致するか。
5. A〜Dの成果がEで実際に使われ、Eがセットの主要目標を達成するか。
6. explanationが前問の利用箇所、小問の必要性、Eへの接続を説明しているか。
7. 問題・正答・解説・採点条件に数学的な矛盾がないか。
8. JSONが完全に有効で、指定セット数を満たすか。

## 生成条件

- セット数: 1セット
- ID: GSET-002
- displayName: テーマ演習 #002
- 対象: 大学数学
- 分野: 曲線・曲面論
- セット全体の目安時間: 60分
- 最終目標: 1つのパラメータ表示曲面について曲率を計算し、幾何学的性質を判定する
- 使用言語: 日本語
```
