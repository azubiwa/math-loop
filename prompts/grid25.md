# 25マス計算の問題セット生成プロンプト

係数だけの回答や零形式の `0` も、完全一致用の正答候補 `acceptedAnswers` に出力します。複数の係数は基底順の係数列として扱います。

コードブロックをAIへ貼り付け、末尾の「生成条件」を変更して使います。既存のLevel問題・テーマ演習と同様に、生成単位、JSON形式、品質基準、内部検査を指定しています。

**出力は追加実装用の問題案です。** 現在の25マス計算は `lib/grid-drills.ts` と `lib/grid25.ts` の生成処理で出題し、任意の問題JSONの取り込みには対応していません。出力を通常問題のJSONや「履歴を読み込む」へ渡しても追加できません。採用時には生成処理・セット選択・保存データ検証を合わせて対応させ、既存セットと記録を保つ必要があります。

リポジトリを参照できるAIには、既存セットを生成して比較するよう指示しています。参照できないAIには、生成条件の索引欄に既存の行・列・演算を渡してください。まずは1演算・1難度で2セット程度の生成を推奨します。

```text
あなたは、数学の反復ドリルの設計・校正・解説執筆を担当する専門家です。
学習アプリ「MathLoop」の「25マス計算」に追加する問題セット案を、末尾の生成条件に従って作成してください。

## 最重要原則

- 1セットは「5つの行データ × 5つの列データ」と、全マスに共通する1つの演算規則から成る。
- マス(i,j)の答えは、左の行データiと上の列データjだけを共通規則で組み合わせて決まる。
- 独立した25問を表へ並べる構成、マスごとの例外規則、前のマスの回答に依存する構成は禁止する。
- 1セット内では同じ基本操作を25回反復する。難解な証明や長い計算を要求しない。
- 通常のLevel問題のA〜E形式や、テーマ演習の依存関係を持つ5小問形式は使わない。
- 答えだけでなく、各マスに対応する短い計算過程を作る。

## 既存内容の確認と新規性

- リポジトリが読める場合、lib/grid-drills.ts、lib/grid25.ts、lib/grid-math.ts、docs/25-grid-design.mdを参照する。型・演算・採点制約は実装を正本とする。
- 現行実装では、既存4演算はbasicのみ各10セット、追加10演算はbasicとstandardを各10セット持つ。実際の最新実装と索引を優先する。
- 既存問題はJSON一覧ではなく生成処理にある。対象演算・難度の全セットを生成して、行・列・規則を比較する。実行できない場合は、完全な索引の提供を求める。
- リポジトリを参照できない場合は、生成条件のEXISTING_GRID25_CATALOGを使う。索引は各セットのdrillId、level、sheet、version、rule、context、rows、columnsを含むこと。
- 対象演算・難度の最大sheetの次から連番を振る。番号を推測しない。索引が不足する場合、JSONを作らず、足りない演算・難度の索引を求める。
- 既存のセット番号を再利用・上書きしない。既存データと今回の出力内で、同じ表、行列の並べ替えだけの表、可換な演算で行と列を交換しただけの表を作らない。
- 反復練習なので同じ演算や定理の再利用、意味のある係数変更は認める。ただし表全体の符号反転や一律の定数倍だけで水増しせず、零・符号・打消し・次数など練習する組合せを変える。
- 同じ軸の5見出しは数学的にも相異なるものにする。行軸と列軸の間で同じ対象を使うことは認める。

## 対応する演算

生成条件で指定された演算だけを作る。各表の次元と座標順序はcontextに明記する。

| drillId | category | 左の行データ | 上の列データ | 求めるもの |
| --- | --- | --- | --- | --- |
| addition | calculation | 整数a | 整数b | a+b |
| multiplication | calculation | 整数a | 整数b | ab |
| fractions | calculation | 有理数a | 有理数b | a+b |
| complex | calculation | 複素数a | 複素数b | ab |
| dot | algebra | ベクトルa | ベクトルb | 標準内積a・b |
| matrix | algebra | Aの第i行 | Bの第j列 | (AB)ij |
| derivative | analysis | xの多項式f | 微分回数n | Dⁿf |
| gcd | structures | 正整数a | 正整数b | gcd(a,b) |
| mod | structures | 整数a | 正整数b | a mod b、0≤余り<b |
| evaluation | geometry | 1形式ω | 接ベクトルX | ω(X) |
| wedge | geometry | 1形式α | 1形式β | α∧β、この順序を固定 |
| differential | geometry | 定数aを含む関数f | aの具体値 | aを定数としてdf |
| exterior | geometry | 定数aを含む1形式ω | aの具体値 | aを定数としてdω |
| pullback | geometry | 写像F | 微分形式ω | F*ω |

- addition、multiplication、fractions、complexのlevelはbasicのみ。他の10演算はbasicまたはstandard。
- dot、matrix、evaluationはbasicで2成分、standardで3成分。内積は実標準内積、評価は標準座標の双対基底を使う。
- matrixはAが5×k、Bがk×5（k=2または3）。左の5行と上の5列でAB全体が得られるようにする。行ベクトルと列ベクトルの役割を明示する。
- derivativeは列をD¹,D²,D³,D⁴,D⁵とし、行には相異なる多項式を置く。
- wedgeは両難度ともR³の定数係数1形式を使う。standardでは混合成分や負係数の組合せを増やす。
- differential、exteriorはbasicで座標(x,y)、standardで(x,y,z)。aを微分する変数に含めない。列のaの値は相異なる5整数にする。
- pullbackはF:R²(u,v)→R²(x,y)。basicは1形式、standardは2形式。係数関数を持つ形式も含める。
- 新しい演算ID、三角関数、積分、Lie括弧、曲率などは今回の仕様に混ぜない。必要なら別の拡張提案として扱う。

## 数学的品質と難度

- 1マスの演算規則、定義域、座標、基底、パラメータの意味を問題文だけで理解できるようにする。
- 基礎は定義や公式の短い適用、標準は同じ操作で成分数・混合項・符号処理が少し増える程度とする。
- 初期値の目安：整数・定数係数は-9〜9、分数の正の分母は2〜9、複素数の実部・虚部は-3〜3、gcd・modの正の整数は2〜100。
- 多項式は少数項・低次数を優先し、微分回数に応じた零の答えも含める。微分用の入力関数は次数7以下、幾何の係数は原則次数3以下、写像成分は原則次数2以下にする。
- 零や打消しは学習に有用だが、意図なく全25マスが同じ答えになる表、ほぼ全てが零になる表は避ける。
- 行列の次元不一致、0による除算、未定義の値、数値近似を必要とする答えを作らない。
- 1形式の評価を内積と同一の概念として説明しない。計算式が似ていても、双対基底の作用に基づくことを説明する。

## 幾何の符号・基底規約

- dxⁱ(∂ⱼ)=δⁱⱼ。
- α=Σaᵢdxⁱ、β=Σbᵢdxⁱなら、α∧βのdxⁱ∧dxʲ（i<j）の係数はaᵢbⱼ-aⱼbᵢ。
- dxⁱ∧dxⁱ=0、dxⁱ∧dxʲ=-dxʲ∧dxⁱ。同じ基底をまとめてから答える。
- df=Σ(∂f/∂xⁱ)dxⁱ。
- ω=ΣPᵢdxⁱなら、dω=Σ(i<j)(∂Pⱼ/∂xⁱ-∂Pᵢ/∂xʲ)dxⁱ∧dxʲ。
- F*ωでは、係数にもx=F₁(u,v), y=F₂(u,v)を代入し、dxをdF₁、dyをdF₂へ置き換える。
- F*(g dx∧dy)=(g∘F)det(DF) du∧dv。行列式の符号を絶対値にしない。
- 例：F(u,v)=(u+v,uv)ならF*(xdy)=v(u+v)du+u(u+v)dv、F*(dx∧dy)=(u-v)du∧dv。
- 零形式も、指定された基底の全係数を"0"で出力する。基底を省略しない。

## 出力形式：問題案JSON

- 出力は有効なJSON配列のみ。各要素は1セット。Markdown、コードフェンス、前置き、後書き、コメント、省略記号を付けない。
- 以下の構造を使う。これは問題案の受け渡し形式であり、現行アプリが直接読み込めるファイルではない。
- スキーマのrows・columns・cellsの例は構造説明のため各1要素で示す。実際の出力では必ず5・5・25要素をすべて埋める。acceptedAnswersも例では1マス分だけ示すが、実際には25マス分を出力する。

{
  "proposalId": "GRID25-wedge-basic-011",
  "category": "geometry",
  "title": "セットの内容が分かる短いタイトル",
  "learningGoal": "この表で反復する基本操作と注意点",
  "acceptedAnswers": [["dx∧dy", "(1)dx∧dy+(0)dx∧dz+(0)dy∧dz", "1,0,0"]],
  "board": {
    "drillId": "wedge",
    "version": 1,
    "sheet": 11,
    "level": "basic",
    "rows": [{"text": "dx+dy", "tex": "\\mathrm{d}x+\\mathrm{d}y"}],
    "columns": [{"text": "dy", "tex": "\\mathrm{d}y"}],
    "cells": [
      {
        "expected": ["1", "0", "0"],
        "basis": ["dx∧dy", "dx∧dz", "dy∧dz"],
        "variables": ["x", "y", "z"],
        "explanation": [
          "(dx+dy)∧dy=dx∧dy+dy∧dy。",
          "dy∧dy=0なので、基底順の係数は1,0,0。"
        ]
      }
    ],
    "context": "R³の標準座標(x,y,z)。基底順はdx∧dy, dx∧dz, dy∧dz。",
    "rule": "左のαと上のβについて、α∧βを求めます。",
    "operator": "∧"
  }
}

- proposalIdはGRID25-{drillId}-{level}-{3桁以上のsheet}。上の011は固定指定ではない。確認した次番号を使う。
- categoryは対応表と一致させる。versionは新しいセット案の初版として1。既存セットの改訂番号として使わない。
- rowsは上から下、columnsは左から右。cellsは行優先の一次元配列：[1行1列,1行2列,…,1行5列,2行1列,…,5行5列]。
- 各cellにrowやcolumnを別途付けない。cells[5*i+j]がrows[i]とcolumns[j]に対応する（i,jは0始まり）。
- textは読みやすいプレーン表記、texはKaTeX用の数式本体。texに$や数式区切りを付けず、JSONのバックスラッシュを正しく二重化する。
- 行列・ベクトルはtexでpmatrixを使う。contextとruleは日本語のプレーン文字列。explanationもプレーン文字列として読める式を使う。
- explanationは各マス2〜4段階を目安に、実際の行・列の値、代入・計算、符号や基底の整理、結論を簡潔に説明する。一般公式のコピーだけで済ませない。
- 通常問題用のcontest、difficulty:A〜E、grade.accepted、grade.groups、knowledgeを追加しない。

## 完全一致用の正答候補

- セット直下のacceptedAnswersは25要素の配列。acceptedAnswers[i]はboard.cells[i]の「回答全体として正しい別表記」の文字列配列とする。boardには追加しない。
- これは問題案の補助データであり、現行アプリの履歴形式や採点処理へ直接読み込むキーではない。現行の係数欄ではexpectedの各成分と多項式の同値性を判定する。
- 各マスの正答候補には形式全体の表記と、次の規則に従う係数のみの表記を含める。数字だけでも意味が一意なら正答候補に必ず追加する。
- basisが1つの微分形式では、基底を省いた係数だけでも正解にする。例：答えが(0)dx∧dyなら["(0)dx∧dy","0dx∧dy","0"]、(2)dx∧dyなら["(2)dx∧dy","2dx∧dy","2"]。係数が多項式なら"2x"、分数なら"1/2"も同じ扱いにする。
- ASCIIのwedge表記も完全一致候補として列挙する。例："(0)dx ^ dy", "0dx^dy", "(2)dx ^ dy", "2dx^dy"。各表記はそのマスの正答と一致するものだけを入れる。^はこの形式表記ではwedgeを表すと解釈し、係数のべき乗と混同しない。
- basisが複数ある場合、全係数を指定基底順にカンマで並べた表記を候補にする。例：2dx+3dyなら"2,3"と"(2,3)"を含め、"2"や"3"だけを正答にしない。係数列の順序と入力方法をcontextにも明記する。
- 複数基底でも全係数が零なら、零形式全体の表記として"0"を必ず追加する。例：basisが["dx∧dy","dx∧dz","dy∧dz"]なら"0,0,0", "(0,0,0)", "0"を含める。ただし現行の複数係数欄では各欄への0入力が必要で、1欄の0が空欄を自動補完する意味ではない。
- 数値・複素数などbasis:["答え"]の問題も、回答全体の正しい表記を列挙する。分数の有限小数表記など厳密に等しい候補は追加してよいが、近似値は禁止する。
- 完全一致は候補文字列全体の一致とする。部分一致、正規表現、数式から数字だけを機械的に抜き出す処理は使わない。説明中の数字や別の基底の係数を誤って正答候補にしない。
- 候補は重複を除き、各マスの問題設定・基底・係数に照らして独立に検算する。JSONの文字列として正しくエスケープする。

## 回答配列と採点形式

- expectedは正答の成分の配列であり、同値な別解のリストではない。
- basis、expectedの長さを一致させる。全25マスでbasisとvariablesを統一する。
- 数値・複素数・内積・行列積・多項式微分・gcd・mod・1形式の評価はbasis:["答え"]。
- 数値・複素数・内積・行列積・gcd・mod・評価はvariables:[]。多項式の微分はvariables:["x"]。
- dfはbasis:["dx","dy"]または["dx","dy","dz"]、variablesは同じ座標順。
- wedgeはbasis:["dx∧dy","dx∧dz","dy∧dz"]、variables:["x","y","z"]。
- 外微分は2次元ならbasis:["dx∧dy"]、3次元ならwedgeと同じ順。variablesは元の座標順。
- pullbackの1形式はbasis:["du","dv"]、2形式はbasis:["du∧dv"]。variablesはどちらも["u","v"]。
- 列のaを代入した後の正答にaを残さない。pullbackの正答にx,yを残さない。
- expectedにはTeXや基底記号を入れない。例：df=2x dx+3dyは["2x","3"]。
- 多項式の正答は展開・同類項整理した簡潔な式。使えるのは許可された変数、小さい整数・有理数、+ - * / ^、括弧、暗黙の乗算。例："2xy-x^2", "x/2"。
- 分母は0でない定数のみ。指数は0〜8の整数。1成分300文字以内。変数分母、負・分数指数、関数、根号、無限大、近似値を出さない。
- 数値は厳密値。分数は既約・正の分母とする。全て零でも空文字ではなく"0"。
- addition、multiplication、fractions、complexの全cellには追加キーlegacyを付ける。形式は{"real": 整数, "denominator": 正整数, "imaginary": 整数}。
- legacyは採点用の正答を表す。整数はdenominator:1, imaginary:0。分数はreal/denominatorを既約にしimaginary:0。複素数はreal+imaginary*iを表しdenominator:1。expectedの表示と必ず一致させる。
- 複素数expectedは"2-3i", "i", "-i", "0"などのa+bi形式。実部・虚部は整数。iを多項式変数として扱わない。
- それ以外の演算にはlegacyを付けない。同値な多項式は専用パーサーで採点する想定とする。

## 出力前の内部検査

全セットの全25マスを実際に計算し、次を検査・修正する。検査報告は出力しない。

1. 指定セット数、演算、難度、連番を満たし、既存・今回の表と重複しないか。
2. 行5個・列5個・セル25個が揃い、行優先の対応が正しいか。
3. 全マスが1つの規則で定まり、条件不足や次元の不一致がないか。
4. 行・列の値から独立に再計算した結果がexpectedと一致するか。既に作ったexpectedの転記を検算にしない。
5. expected、basis、variables、legacy、解説の結論が整合するか。acceptedAnswersが25マスに対応し、各候補が正しいか。1基底の係数のみの答えと零形式の"0"が含まれ、複数係数の一部だけを誤って正答にしていないか。
6. 数式表示用texとtextが同じ対象を表し、JSONとして正しくエスケープされているか。
7. 幾何は基底の順序、wedgeの符号、係数の代入を全件確認したか。外微分ではd(dω)=0、pullbackでは適用できる場合にd(F*ω)=F*(dω)も検算に使う。
8. 不正入力や数値近似に頼らず、全正答が指定の回答形式で入力できるか。
9. 各解説が当該マスの具体的な計算を説明し、答えと矛盾しないか。
10. JSON構文、キー、要素数、IDが正しいか。リポジトリで実行可能なら、gradeDrillCellで全正答を検証する。未実行の検証を実行済みとみなさない。
```

## 生成後のレビューと追加

1. 行・列から全25マスを再計算し、上の内部検査に沿って別途レビューします。既存の `review-generated-problems.md` は通常問題のスキーマ用なので、そのまま適用しません。
2. `board.cells` の正答を `gradeDrillCell` で採点できるか確認します。これは入力形式の確認であり、問題の数学的な独立検算の代わりにはなりません。
3. 採用時に、問題生成処理、UIのセット数、`lib/grid-history.ts` の対応範囲・再生成検証を更新します。現状の番号上限は10なので、#011以降のJSONを作るだけでは出題できません。
4. 既存の同じ演算・難度・番号の問題は変更しません。旧記録の再読込と既存セットの再現性を確認してから公開します。
